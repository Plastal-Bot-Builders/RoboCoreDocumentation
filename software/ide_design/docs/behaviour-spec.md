# RoboCore IDE — behaviour spec and test checklist

Every control in the RoboCore IDE, what it must do, and where to try it in the Figma prototype ([RoboCore IDE — UI/UX Design](https://www.figma.com/design/P7i2WBM8G96B2fTPHpp8yi), page 05). Blocks are Google Blockly; the code editor is Monaco.

Each row is one test case. Run it in the prototype now, and on the built app later. IDs are stable: add new rows at the end of an area.

145 test cases in 16 areas. Generated from `figma-plugin/src/10d_spec_data.js` by `node tools/spec_md.js`; do not edit this file by hand.

## Implementation notes

| Topic | Note |
|---|---|
| Hardware-first blocks | The block set follows the idea behind LEGO SPIKE Prime (not its art): blocks name what the robot does. Each action has a “for …”, a “start …” and a “stop” form; each sensor has a value, a yes / no question and a “when …” hat. RoboCore V2 has everything built in, so there are no port dropdowns (servos 1–4 only). |
| RoboCore library work | Blocks marked “new:” in the Block catalogue need helpers in firmware/RoboCore: RoboCoreDrive (move by cm / rotations / seconds, turn by degrees with the IMU, steer, speed, wheel size), per-wheel motor control and position (needs the encoder counts per wheel turn), RoboCoreServos, yaw / pitch / roll and tilt / shake checks, LED brightness, melodies, battery %, a program timer, and “just happened” edge checks for the when-hats. |
| When-hats in C++ | Phase 1: each when-hat becomes an if (…justHappened()) { … } checked at the top of loop(), so the generated code stays readable. Phase 2 (later): run each hat as its own FreeRTOS task for true parallel scripts, as SPIKE does. |
| Embedding in Flutter | Blockly and Monaco are web libraries. In the web build host them in an HtmlElementView with a small JS bridge (like web/robocore_usb.js); in the native apps use a WebView. AppState stays the single source of truth. |
| Browser shortcuts | In browsers Ctrl/⌘+R reloads the page and Ctrl+U opens the page source, so the web app uses Ctrl+Enter (Verify) and Ctrl+Shift+Enter (Upload); the native apps keep the Arduino keys. |
| Accessibility | Use Blockly’s keyboard navigation; every icon button has a label and a tooltip; focus = navy border + yellow halo; text stays at 4.5:1 or more. |
| Licences | Blockly Apache 2.0; Monaco MIT; esptool-js Apache 2.0. List them in About. |

## What the prototype cannot do

| Limit | Why and what to do |
|---|---|
| Choices do not carry over | Figma Starter has no prototype variables, so a value picked on one screen (board, baud, toggles) is not remembered on the next screen. The spec above says what the app must remember. |
| Right-click | Figma prototypes have no right-click: clicking a block or the empty workspace opens its context menu. |
| Typing | Typing is simulated: clicking a field shows it filled in. |
| Dark theme | Navy is shown statically on page 06; the Theme choice on Settings changes only the radio. |
| Demo depth | Only “play beep” can be dragged from the flyout, and only the Blink program’s fields have editors. Projects other than Blink LED and Obstacle avoider open the Blink screens. |
